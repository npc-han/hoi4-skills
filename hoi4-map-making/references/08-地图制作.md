# 08-地图制作(Map Modding)

地图文件格式、省份颜色系统、新建省流程与常见错误——HOI4 mod 制作中最硬核的部分。


> ⚠️ 地图文件彼此强关联(provinces.bmp ↔ definition.csv ↔ 战略区 ↔ 州 ↔ 建筑),改一处必须联动改多处,否则出现 03-2.6 那一堆地图报错。**修改前务必备份地图**。

---

## 1. 核心文件与作用

| 文件 | 位置 | 作用 |
|---|---|---|
| `provinces.bmp` | `map/` | 省份底图:每个省份用**唯一 RGB 颜色**填充 |
| `definition.csv` | `map/` | 把 RGB 颜色映射到省份 ID,并定义类型/沿海/地形 |
| `adjacencies.csv` | `map/` | 特殊连接(岛屿间虚线、不可通行地形的通道) |
| `adjacency_rules.txt` | `map/` | 邻接规则 |
| `strategicregions/*.txt` | `map/` | 战略区:省份归属、海省地形、天气、建筑放置 |
| `states/*.txt` | `history/states/` | 州:省份组合、人力、state_category、建筑 |
| `supply_nodes.txt` / `rocketsites.txt` | `map/` | 补给节点 / 火箭发射场 |

## 2. definition.csv 格式

每行一个省份,逗号分隔 6 个字段:

```
<省份ID>,<R>;<G>;<B>,<type>,<coastal>,<terrain>
200,0;0;0,land,no,plains
201,128;0;0,sea,yes,ocean
```

- **省份 ID**:数字,唯一。
- **RGB 颜色**:与 provinces.bmp 中绘的颜色**完全一致**;同色 = 两个省被当做一个省。
- **type**: `land` / `sea` / `lake`。
- **coastal**: `yes` / `no`(沿海)。
- **terrain**: 陆省地形写在这里(如 plains/forest/mountain);**海省地形在战略区文件里分配**。
- 若 definition.csv 中某行缺失或顺序错位,其后所有颜色的 ID 映射全部偏移——症状是"省份沿海与否不一致"报错和地形模式破碎(见 03-2.6)。

## 3. provinces.bmp 硬性要求(违反即崩溃)

| 要求 | 值 |
|---|---|
| 尺寸 | 宽高都必须是 256 的倍数(如 8192×8192) |
| 文件大小 | 不超过 40 MiB |
| 位图一致性 | 各 bmp(terrain/heightmap 等)尺寸必须一致(唯一例外 `trees.bmp`) |
| DIB 头 | 用 BITMAPINFOHEADER,不要 BITMAPV5HEADER;不设编码标志 |
| 格式 | 24-bit BMP(推荐 paint.net 导出) |

> 违反以上任一规则,崩溃日志的 LastRead 可能显示 `gfx/models/supply/railroad.shader`(见 03-3)——先查 bmp。

## 4. 新建省份完整流程(Workflow)

按顺序做,缺一步省份就是"死的":

1. **绘色**:把原版 `provinces.bmp` 复制到 mod,用 PS/GIMP 以 1 像素铅笔涂**未在 definition.csv 中使用过的 RGB 颜色**。
2. **注册**:在 `definition.csv` 添加对应行(ID + 颜色 + type + coastal + terrain)。
3. **Nudger 校验**:进游戏开 Nudge → 它会生成 `definition.csv.fixed.csv`(**优先于手改的 definition.csv**)→ 建议先让 Nudge 生成,再编辑 `.fixed.csv`,不要手改 definition.csv 后又被 Nudge 覆盖。`Generate RGB` 按钮会给出保证不冲突的颜色。
4. **归入战略区**:把省份加进 `map/strategicregions/` 对应文件(否则省份不属于任何战略区)。
5. **归入州**:在 `history/states/` 的州文件把省份加进该州;**新州必须写 `manpower` 和 `state_category`**,否则 "State #X does not have a category defined"。
6. **建筑与单位**:更新 `map/buildings.txt`(建筑位置)和 `history/units/`(驻军),否则 "map building location is not within specified state"。
7. **收尾**:把 `definition.csv.fixed.csv` 重命名为 `definition.csv`,删除 `definition.csv.cache`,再放进 mod。

> 数量限制:游戏可显示约 19K–22K 省份(目前最高纪录 21,939)。视觉上孤立的岛屿(如马尔代夫)必须定义为**一个省**,军队才能整体占据。

## 5. 邻接(Adjacencies)

- 岛屿之间、不可通行地形之间的特殊连接在 `adjacencies.csv` 中定义。
- **海/陆邻接必须手动指定 through 省**(途经省)。常见的错误消息:

```
Adj between 1399 and 1515 is not adjacent with THROUGH = 220
```
→ 1399 和 1515 之间没有经过 220 号省的路径——邻接的两个端点必须与 through 省真实相邻。

- `adjacency_rules.txt` 定义规则;不可通行地形可在州/历史文件中用 `impassable = yes`。

## 6. 战略区与地形(Strategic Regions & Terrain)

```
# map/strategicregions/00_strategicregions.txt 示例结构
strategic_region = {
    id = 1
    name = STRATEGICREGION_1
    provinces = { 200 201 202 }
    static_modifiers = { }          # 战略区修正
    weather = { }                   # 天气
}
```

- 省份 → 战略区 → 州 三层归属必须一致;战略区文件里也定义**海省地形**、天气、建筑放置(港口等)。
- 修改地图后战略区没更新 = 省份"不属于任何地方",游戏内表现为不可用。

## 7. 常见错误速查(完整版见 03-2.6)

| 错误原文 | 原因 |
|---|---|
| `Map invalid X crossing. Please fix pixels at coords` | 四省共角(地图横向循环,边界也可能出现) |
| `Province X has TOO LARGE BOX` | 省宽/高 > 地图 1/8,通常两个省共色 |
| `Province X has only N pixels` | 低于最小像素(`NGraphics.MINIMUM_PROVINCE_SIZE_IN_PIXELS`) |
| `Bitmap and province definition disagree on whether or not province X is coastal` | bmp 与 csv 不一致,或 csv 缺行导致映射错位 |
| `Province has no pixels in provinces` | 编辑后省无像素,需手动修 |
| `State #743 does not have a category defined` / `has no people living in it` | 新州缺 state_category / manpower |
