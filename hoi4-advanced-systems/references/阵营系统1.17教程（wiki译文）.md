## 基础

### 无 DLC

如果你没有购买 DLC「[No Compromise, No Surrender](</No_Compromise,_No_Surrender> "No Compromise, No Surrender")」（不妥协，不投降），那么你将无法使用新阵营系统的大部分功能。如果你不想让 mod 依赖 DLC 拥有权，但仍想使用基础阵营，你可以使用 [create_faction_from_template](</Effect#create_faction_from_template> "Effect")。

### 有 DLC

有了 DLC，阵营几乎在每一个方面都可以被充分 mod 修改。其大部分内容基于 [模板](</Faction_modding#Templates> "Faction modding")（template），模板包含阵营的其他组成部分，包括 [目标](</Faction_modding#Goals> "Faction modding")（goals）、图标、颜色、[规则](</Faction_modding#Rules> "Faction modding")（rules）、[宣言](</Faction_modding#Manifests> "Faction modding")（manifests）。创建阵营时你仍然使用 [create_faction_from_template](</Effect#create_faction_from_template> "Effect")。

#### 简要概览

  * [目标](</Faction_modding#Goals> "Faction modding")（Goals）- 面向多个国家或领袖国家的「任务」
  * [规则](</Faction_modding#Rules> "Faction modding")（Rules）- 阵营内部使用的一套规章
  * 图标（Icon）- 阵营的视觉标志
  * 颜色（Color）- 阵营地图模式中使用的阵营颜色，通常与领袖颜色一致
  * [宣言](</Faction_modding#Manifests> "Faction modding")（Manifests）- 全局、持续性的目标，用于根据条件为阵营提供修正器或规则。
  * [成员国升级](</Faction_modding#Member_upgrades> "Faction modding")（Member upgrades）- 人力共享
  * [模板](</Faction_modding#Template> "Faction modding")（Template）- 将以上所有内容组合在一起的方式

## 目标

### 概览

阵营的目标（goal）是一种无需使用任务（missions）或事件（events），就能让多个国家拥有「任务」的方式。游戏中有三种类型的目标：短期目标（Short-term）、中期目标（Medium-term）和长期目标（Long-term）。它们定义在

`common/factions/goals/*.txt` 中，每个阵营在游戏中最多可以拥有三种类型中的一种。**阵营并非必须一开始就拥有目标。** 默认作用域是阵营领袖，FROM 是查看当前目标的阵营成员。**`complete_effect, remove_effect, cancel_effect` 内部不支持 FROM。**

### 结构

`goal_id` - 你的目标 id，必须唯一。

`name` - 目标可见名称的[本地化](</Localisation> "Localisation")键

`description` - 目标可见描述的[本地化](</Localisation> "Localisation")键

`category = short_term/medium_term/long_term` 决定目标被分配到哪个类别。类别之间没有区别，但良好的实践是：把较容易的目标放在 short_term，中等难度的目标放在 medium_term，长期目标放在 long_term。

`group = GROUP_ID` - 用于排序目标的组，接受国策中的[搜索过滤器](</National_focus_modding#Search_filters> "National focus modding")以及你自定义的任何内容，创建新组的方式与国策[搜索过滤器](</National_focus_modding#Search_filters> "National focus modding")完全相同。

`locked_goal = { yes/no }` - 使目标「锁定」。目标将无法被手动替换，除非你完成它。

`is_manifest = { yes/no }` - 决定它是目标还是[宣言](</Faction_modding#Manifests> "Faction modding")。默认设置为 no（即它是目标）。

#### 触发器

`visible = { }` - 一个[触发器](</Trigger> "Trigger")块，每帧持续检查条件是否满足；若要目标在目标选择界面中可见，此块必不可少。由于它每帧检查，因此最好把国家或 DLC 检查放进 allowed 中。

`available = { }` - 一个[触发器](</Trigger> "Trigger")块，每帧持续检查条件是否满足；若要目标在目标选择界面中可被选择，此块必不可少。如果条件不满足，目标将无法被选择；但与 visible 的区别在于，它仍会显示，并在悬停时说明为何无法被选择。

`allowed = { }` - 一个[触发器](</Trigger> "Trigger")块，仅在游戏开始或读取存档时被检查，主要用于将目标限制给某个国家（如 `tag = BHR` 或 `original_tag = POL`）和/或某个 DLC（如 `has_dlc = "One Step Back"`）。如果目标的 allowed 条件未满足，它将永远不会出现在选择列表中，除非在重新加载存档时条件变为满足；但通过 `add_faction_goal` 手动指定会绕过此检查。如果省略，则视为始终允许。**此检查只进行一次！**

`completed = { }` - 一个[触发器](</Trigger> "Trigger")块，决定目标是否已完成。此处应放置所有你希望阵营完成的目标条件。默认作用域是阵营的领袖。

`cancel = { }` - 一个[触发器](</Trigger> "Trigger")块，一旦条件为真，决定目标是否应被移除。会触发目标的 cancel_effect。

#### 效果

`complete_effect = { }` - 一个[效果](</Effect> "Effect")块，在完成目标时执行效果；默认情况下只有阵营领袖会因完成目标而获得奖励（因为目标的默认作用域是领袖）。

`select_effect = { }` - 一个[效果](</Effect> "Effect")块，在目标被选择后执行一次效果。**如果目标是通过阵营模板添加的，此块不会触发。**

`remove_effect = { }` - 一个[效果](</Effect> "Effect")块，在目标被移除后执行效果。与 cancel_effect 的唯一区别是：如果目标被更换，会执行此效果；而另一个只在目标因其 `cancel` 触发器中的条件满足而被取消时执行。

`cancel_effect = { }` - 一个[效果](</Effect> "Effect")块，在目标被取消后执行效果。与 remove_effect 的唯一区别是：如果目标因其取消条件满足而被取消，会执行此效果；如果目标被更换，则会执行另一个。

#### 基于进度的目标

目标主要使用 `completed` 触发器配合 `complete_effect` 为完成的目标发放奖励。虽然这是完成目标的主要方式，但并不是唯一的方式。ratio_progress 是一个块，它能把目标转变为持续型目标，开辟出新的使用方式。想象一下，你想把目标建立在占领某阵营的土地之上，或者基于阵营的资源数量；也许你想要一个任务，在阵营中 80% 的省份拥有工厂时完成。这些都可以通过 ratio_progress 实现。

`ratio_progress = { }` - 一个可以在其中实现上述所有功能的块。

##### ratio_progress 的参数

下面提到的所有内容都必须用在 ratio_progress 内部，否则无法生效。

`total_amount_collection = collection_id` - 使用一个 collection 来定义参与完成度计算的元素。

`completed_amount_collection = collection_id` - 使用一个 collection 来检查 `total_amount_collection` 中哪些元素已完成。

**代码示例：**


    ratio_progress = {
    		total_amount_collection = {
    			input = collection:african_states
    		}
    		completed_amount_collection = {
    			input = collection:african_states
    			operators = {
    				limit = {
    					is_controlled_by_ROOT_or_ally = yes
    				}
    			}
    		}
    }

_一旦阵营领袖或任何阵营成员控制所有非洲省份，这段代码将使目标完成度达到 100%。关于更多 collection 信息或如何使用它们，请参阅 `common/collections/_documentation.md`_

`total_amount = MY_VALUE` - 定义最大数量的变量或固定数值。

`completed_amount = MY_OTHER_VALUE` - 定义你已完成数量的变量或固定数值。

**代码示例：**


    ratio_progress = {
    		total_amount = 10 
    		completed_amount = myVar # 8
    }

_一旦 myVar 变成 10，这段代码将使目标完成度达到 100%，提示框会显示你已完成 8/10_

**同一类型下，collection 和非 collection 版本不能同时使用，例如 total_amount 和 total_amount_collection 互斥。但你可以同时使用 total_amount_collection 和 completed_amount。除非使用 auto_complete = yes，否则比例达到 100% 时目标不会被完成。**

`progress_sections = { }` - 一个包含分段的块，分段的工作方式与[力量平衡](</Balance_of_power_modding> "Balance of power modding")（bop）中的分段相同。它可以用于：当完成度处于某个阈值区间内时，启用修正器。

**示例代码：**


    progress_sections = {
          my_first_milestone = {
            min = 0
            max = 0.49
            modifier = {
              stability_factor = 0.05
            }
          }
          my_second_milestone = {
            min = 0.5
            max = 0.69
            modifier = {
              army_attack_factor = 0.05
            }
          }
          my_third_milestone = {
            min = 0.7
            max = 0.9
            modifier = {
              war_support_factor = 0.05
            }
          }
        }

`min = X` - 分段生效所需的最小值。以百分比计，1 为最大值，0 为最小值

`max = Y` - 分段生效所需的最大值。以百分比计，1 为最大值，0 为最小值

`modifier = { }` - [修正器](</Modifiers> "Modifiers")块，分段生效期间所有成员获得的修正器。

`rule = { }` - 阈值生效期间适用于所有成员的规则。

**补充内容**

`auto_complete = { yes/no }` - 如果进度达到 100%，自动完成目标；仅当目标中存在 ratio_progress 时有效。可与 range 配合使用，一旦 range = { max = X } 所定义的比例完成，目标即告完成。

`completed_amount_custom_tooltip` - 用你选择的任何内容覆盖已完成数量的默认提示框。

`total_amount_custom_tooltip` - 用你选择的任何内容覆盖总数量的默认提示框。

`range = { min = X max = Y }` - 定义上述计算出的比例如何映射到目标的进度：如果 max = 0.8，意味着一旦总量与已完成量之间的比例达到 80% 或以上，目标即完成。如果 min = 0.2，意味着比例达到 20% 时目标完成度为 0%。

**min 和 max 都是可选的，默认 min = 0，max = 1。min 实际上可以大于 max，此时进度会随比例下降而上升，反之亦然。**

`scale = { }` - [修正器](</Modifiers> "Modifiers")，一旦进度达到 100%（可与 range 配合使用），阵营领袖获得。

`reversed = { }` - [修正器](</Modifiers> "Modifiers")，一旦进度变为 0%（可与 range 配合使用），阵营领袖获得。

#### AI

`ai_will_do = { }` 决定 AI 用此目标替换空目标槽位的可能性，与游戏中所有其他 ai_will_do 块的工作方式完全相同。更多信息请参阅 [AI 修改](</AI_modding> "AI modding")（AI_modding）。

## 宣言

宣言（Manifest）是一种全局、持续性的目标，用于根据条件为阵营提供修正器或规则。它们定义在 `common/factions/goals/*.txt` 中。此类条件的例子可以是占领的土地，或拥有你的意识形态的国家。与目标相比，你无法在游戏中更换宣言；宣言在阵营的模板中设置，每个阵营都应有一个宣言。

#### 结构

`manifest_id` - 你的宣言 id，必须唯一。

`name` - 目标可见名称的[本地化](</Localisation> "Localisation")键

`description` - 目标可见描述的[本地化](</Localisation> "Localisation")键

`is_manifest = yes` - 决定它是目标还是[宣言](</Faction_modding#Manifests> "Faction modding")。默认设置为 no（即它是目标）。宣言必须设置此项。

#### 进度

宣言的其他参数只有 `ratio_progress` 和普通的 `progress`，关于 `ratio_progress` 请参阅[基于进度的目标](</Faction_modding#Progression_based_goal> "Faction modding")一节。

`progress = { }` - 一个块，可以在其中添加多个 progress_sections。基本上是 ratio_progress 的劣化版。不要使用它。

`progress_sections = { }` - 一个包含分段的块，分段的工作方式与[力量平衡](</Balance_of_power_modding> "Balance of power modding")（bop）中的分段相同。它可以用于：当完成度处于某个阈值区间内时，启用修正器。

#### 宣言代码示例


    my_manifest_id =  {
     name = my_manifest_name
     description = my_manifest_desc
     is_manifest = yes
    
     ratio_progress = {
       total_amount_collection = {
         input = collection:african_states
       }
    
       completed_amount_collection = {
         input = collection:african_states
         operators = {
           limit = {
             is_controlled_by_ROOT_or_ally = yes
           }
       }
     }
    
     scale = {
       stability_factor = 0.1
     }
    
     reversed = {
       stability_factor = -0.1
     }
    
     range = { max = 0.67 min = 0.42 }
    
     progress_sections = {
       my_section = {
         min = 0.1
         max = 0.3
    
         modifier = {
           stability_factor = 0.1
         }
       }
    }

## 规则

规则（Rule）是阵营内部使用的一套规章。规则可以定义阵营的运作方式，也可以仅根据当前生效的规则提供修正器。规则有自己的类型（type）和组（group）。类型决定规则在何种情况下适用，以及会使用什么作用域。组用于把相同用途的规则合并到一个类别中。**规则只有在被添加到至少一个规则组中时才会显示。** 规则可以定义在 `"common/factions/rules/any_name.txt"` 中。

#### 语法

faction_rule_id = { } - 你的规则 id，必须唯一。

type = type_token - 决定你的规则的类型，可以是任何值，但游戏使用这些预定义标记来处理游戏内阵营规则。

特殊 type_token 值  | 定义  | 作用域   
---|---|---  
joining_rule  | 检查一个国家是否可以加入阵营  | ROOT = 加入国，FROM = 阵营领袖   
war_declaration_rule  | 检查谁可以宣战  | ROOT = 宣战国，FROM = 目标国   
call_to_war_rule  | 检查谁可以发起参战呼吁  | ROOT = 呼吁参战国，FROM = 目标国   
member_rules  | 检查成员是否可以更改阵营目标（注意：文档可能有误）  | ROOT = 阵营领袖   
change_leader_rules  | 检查哪个国家可以成为阵营领袖  | ROOT = 成为阵营领袖的国家   
peace_conference_rules  | 应包含一个在和平会议期间应用的 peace_action_modifiers 列表  | ROOT = 阵营领袖   
  

#### 触发器

`visible = { }` - 一个[触发器](</Trigger> "Trigger")块，每帧持续检查条件是否满足；若要规则在规则列表界面中可见，此块必不可少。

`available = { }` - 一个[触发器](</Trigger> "Trigger")块，每帧持续检查条件是否满足；若要规则在规则列表中可被选择，此块必不可少。如果条件不满足，规则将无法被选择；但与 visible 的区别在于，它仍会显示，并在悬停时说明为何无法被选择。

`can_remove = { }` - 一个[触发器](</Trigger> "Trigger")块，决定规则在当前生效时是否可以被移除。默认作用域是阵营领袖。默认为真，即规则允许被移除。

`trigger = { }` - 一个[触发器](</Trigger> "Trigger")块，用于定义规则。例如，块内的 `is_major = yes` 将使只有主要国家才允许使用此规则。

`government_in_exile_allowed_trigger = { }` - ？

`dismiss_member_trigger = { }` - 特殊的[触发器](</Trigger> "Trigger")块，用于定义谁可以被踢出阵营。工作方式与 trigger 完全相同，但用于定义谁可以被逐出阵营。

#### 修正器

`modifier = { }` - [修正器](</Modifiers> "Modifiers")块，规则生效期间所有成员获得的修正器。

`peace_action_modifiers = { }` - 特殊块，当 peace_conference_rules 类型生效时可用。用于在和平会议期间应用修正器。和平行动修正器可以在 `"common/peace_conference/cost_modifiers"` 中找到。**该修正器的启用触发器不会运行——只要规则处于生效状态，修正器就处于启用状态。**

#### 效果

`effect = { }` - 一个[效果](</Effect> "Effect")块，为规则执行效果。

#### AI 块

`ai_will_do = { }` 决定 AI 选择此规则的可能性，与游戏中所有其他 ai_will_do 块的工作方式完全相同。更多信息请参阅 [AI 修改](</AI_modding> "AI modding")（AI_modding）。

#### 本地化

更多信息请参阅[本地化](</Localisation> "Localisation")（Localisation）。


    my_faction_rule_id: "My faction rule name!"

#### 规则组

规则组（Rule group）- 用于把相同用途的规则合并到一个类别中。它们定义在 `"common/factions/rules/groups"` 中。建议将同一类型的所有规则放在同一组中。不过这并不是强制的。一个组也不一定包含某类型的所有规则。

##### 语法

`group_id = { }` - 你的组 id，必须唯一。

`default_rule = rule_id` - 用于定义组内默认使用的规则。

`rules = { }` - 此组中的规则列表，你可以直接在组内定义规则，但不推荐这样做。

#### 代码示例

**规则：**


    my_rule_id = {
    	type = joining_rule 
    
    	trigger = {
    		original_tag = ITA
    	}
    
    	modifier = {
    		weekly_manpower = 1000
    	}
    	ai_will_do = {
    		base = 10
    	}
    }
    
    my_rule_2_id = {
    	type = my_custom_type
    
    	visible = {
    		original_tag = SOV
    	}
    
    	available = {
    		has_political_power > 200
    	}
    	can_remove = {
    		always = no
    	}
    
    	trigger = {
    		is_faction_leader = yes
    	}
    
    	effect = {
    		declare_war_on = {
    			target = ENG
    			type = annex_everything
    		}
    	}
    }

**规则组：**


    rule_group_my_custom_rules_1 = {
    	default_rule = my_rule_id
    	rules = {
    		my_rule_id
    	}
    }
    
    
    rule_group_my_custom_rules_2 = {
    	rules = {
    		my_rule_2_id
    	}
    }

## 成员国升级

成员国升级（Member upgrades）- 阵营中使用的一种机制，可以由阵营领袖更改。它只影响每个阵营成员向共享人力池贡献的兵力数量，该人力池可用于所需驻军。**建议一个组中有 4 个成员国升级，因为这是界面为其准备的默认数量。**

#### 语法

`member upgrade_id = { }` - 成员国升级的 id，应唯一，用于创建新实例的块。

`name` - 阵营成员国升级可见名称的[本地化](</Localisation> "Localisation")键。非必需，默认使用组名称。

`description` - 阵营成员国升级可见描述的[本地化](</Localisation> "Localisation")键。非必需，默认使用组描述。

`icon` - 激活时显示的图标。会覆盖组的图标。

`upgrade_cost` - 将此升级替换为另一个升级所需的阵营倡议数量。

`bonus` - 决定国家贡献兵力数量的数值。

#### 组

`member upgrade_id = { }` - 成员国升级组的 id，应唯一，用于创建新实例的块。

`name` - 阵营成员国升级可见名称的[本地化](</Localisation> "Localisation")键。

`description` - 阵营成员国升级可见描述的[本地化](</Localisation> "Localisation")键。

`icon` - 激活时显示的图标。

`upgrades = { }` - 此组内的阵营升级，此列表将按其 bonus 排序。

`upgrade_type = faction_member_upgrade_manpower` - 目前唯一受支持的类型，其他类型不会显示，可用于覆盖默认类型。

`default_upgrade = upgrade_id` - 用于设置默认的成员国升级。**注意：被选为默认的升级应包含在 upgrades 块中。**
