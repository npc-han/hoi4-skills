# 04-制作注意事项与最佳实践(Best Practices)

项目级组织规范与新手避坑清单——"从零搭一个 mod"的骨架知识。


---

## 1. 标准目录结构(Folder Structure)

mod 文件夹(通常 `Documents/Paradox Interactive/Hearts of Iron IV/mod/<Mod名>/`):

| 目录 | 放什么 |
|---|---|
| `common/` | 国策 `national_focus/`、事件 `events/`、决议 `decisions/`、国家精神 `ideas/`、科技 `technologies/`、人物 `characters/`、法律 `laws/`、意识形态 `ideologies/`、装备 `units/`、defines 等 |
| `history/` | 国家历史 `countries/`、州定义 `states/`、将领 `general/`、开局军队 `units/` |
| `events/` | 事件文件(与 common/events 配合,顶部 `add_namespace`) |
| `localisation/` | 本地化 yml(覆盖原版放 `replace/` 子文件夹) |
| `map/` | provinces.bmp、definition.csv、strategicregions、buildings.txt、supply_nodes 等 |
| `gfx/` | 贴图、模型、旗帜 |
| `interface/` | `.gfx` 注册文件(spriteType)、`.gui` 界面文件 |
| `music/`、`sound/` | 音乐、音效 |
| 根目录 | `descriptor.mod`(描述文件,见 02) |

> 提醒:`.gfx` 注册文件放 `interface/`,不是 `common/interface/`——放错整个 mod 所有图片失效(见 03-2.8)。

## 2. 从零起步清单(Minimal Viable Mod)

最小可运行 mod 最少需要:
1. `descriptor.mod`(name/path/tags/supported_version,见 02)
2. 一个能被游戏看到的改动(哪怕只有一行:如 `common/national_focus/` 里加一个国策,或 `history/countries/` 改一条)
3. 对应的本地化条目(否则显示 undefined)

**建议先用 launcher 创建骨架 mod**,再手动添加内容;骨架 mod 同时验证了路径与编码环境正确。

## 3. replace_path 使用注意

- `replace_path` = 用你的文件夹**整个替换**原版同名文件夹(不是合并)。
- 只在确实需要替换时用;覆盖整个文件夹时**必须自带 generic 文件**(详见 03-第 4 节)。
- 根 .mod 与 descriptor.mod 都要写才生效。

## 4. 文件加载顺序与命名(见 01-第 6 节)

- 文件名按 ASCII 顺序加载,`00_` 早、`zz_` 晚;被引用对象必须先加载。
- 覆盖原版文件 = 文件名与原版**逐字一致**(大小写、路径)。
- 版本敏感文件(如 `common/defines/`)用序号靠后的覆盖文件,不要复制原版(见 02-5)。

## 5. 维护性(Maintainability)

- **用 Git 版本控制**:mod 代码是文本,git 是最佳伴侣;地图等二进制文件也要备份(修改前备份原版地图)。
- 每次改动小步验证:改一处 → 启动测试 → 再看 error.log,不要攒一大包改动再查。
- 修改前**备份**:覆盖原版文件夹前把原文件复制出来。
- 保留原版游戏文件完好:不要在游戏本体文件夹里直接改(虽然能热加载,但破坏多人兼容,且扩展时容易出问题)。

## 6. 兼容性与版本管理(Compatibility)

- `supported_version` 声明支持的游戏版本;游戏大版本更新(mod 可能失效)时参考 `11-版本与兼容\` 的迁移指南。
- 小版本更新后检查:Defines 是否被改(不要复制 00_defines.lua 的原因,见 02-5)、effect/trigger 是否改名/移除(旧名解析成功但什么都不做——静默失败,见 常见报错解读.md 静默清单 #1)。
- 多 mod 兼容:文件前缀命名空间化(如 `my_mod_`),避免覆盖他人 mod 的同名文件。

## 7. 开发工作流(Workflow)

```
1. 规划功能 → 2. 建骨架 → 3. 写代码(参考模板) → 4. 补本地化 → 5. -debug 启动测试
→ 6. 查 error.log 修复 → 7. 清空日志重测 → 8. Git 提交 → 9. 发布(创意工坊)
```

> 提醒:开发期间始终带 `-debug` 启动;发布前再用干净环境验证一遍。
