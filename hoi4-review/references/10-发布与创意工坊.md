# 10-发布与创意工坊(Publishing & Steam Workshop)

mod 发布流程、descriptor 文件细节、自动化发布与版本管理。


---

## 1. 发布流程(launcher 上传)

**必须通过 launcher 创建并上传**,手工搭的 mod 不会出现在上传列表:

1. 启动器 → **Mods** 标签页 → **Mod Tools** → **Create Mod**:填名称、版本、目录(如 `mod/1956_beta`)、tags。
2. 启动器 → "All installed mods" → 选中 mod → **Upload mod** → 确认上传。
3. **上传列表里没有你的 mod?** 说明它不是用 launcher 创建的:新建一个 mod,把你的文件复制进去,就会出现在列表里。

## 2. 文件要求(关键细节)

| 文件 | 要求 |
|---|---|
| 本地 `.mod` 文件 | 只给本地 launcher 用,**上传时不上传**;与 mod 文件夹内 descriptor.mod 信息一致 |
| `descriptor.mod` | 必须在 mod **文件夹内**,名字**必须恰好是 descriptor.mod**;⚠️ **不要用 UTF-8 BOM 保存**(与本地化 yml 必须带 BOM 相反!) |
| `thumbnail.png` | 可选;建议 1:1 比例、<1 MB |
| `tags` | 创意工坊筛选标签,可选 |
| `remote_file_id` | 上传后写入 .mod/descriptor.mod 的创意工坊 ID(自动生成,别手动删) |

descriptor 内容(行顺序无所谓):

```
name="My Mod"
path="mod/My_Mod"            # 根目录 .mod 需要;descriptor.mod 不写 path
tags={
    "Alternative History"
}
picture="thumbnail.png"
supported_version="1.17.*"   # 游戏版本兼容声明(可 "1.17.*" 通配)
version="1.0b"               # mod 自己的版本号
```

> ⚠️ **一致性铁律**:本地 `.mod` 与 `descriptor.mod` 里的 `name`/`version`/`supported_version` 要保持一致,否则启动器与游戏读到的 mod 名/版本不同,表现为"mod 不生效"等诡异问题(静默失败清单 #10)。版本格式见 02-4(supported_version 两个点)。

## 3. 更新与版本管理

- 上传过的新版本会在创意工坊更新,**不要删掉再重传**(会丢失订阅与 ID)。
- 大版本更新后:改 `supported_version` → 用 03 流程回归测试 → 再上传。
- 建议 Git 管理代码 + 每次发布打 tag(本地 `11-版本与兼容\` 有迁移流程)。

## 4. 自动化发布(可选)

- **pdx-steam-workshop-publisher-action**(GitHub Action): https://github.com/Yard1/pdx-steam-workshop-publisher-action
  自动上传 HOI4 mod 到创意工坊,需要 Steam 登录(含邮箱 Steam Guard,经 POP3)、Paradox 账号凭据、mod 路径。
- 其他工具(游戏内上传仍是标准流程):创意工坊在 1.9.0 之后不再以 .zip 存储 mod(直接文件目录)。

## 5. 发布前检查清单

```
□ -debug 完整跑一遍,error.log 无新条目(03 流程)
□ 所有功能测试通过(含 AI 行为)
□ 本地化齐全(无 undefined、无 loc key collisions)
□ descriptor.mod 与 .mod 信息一致、无 BOM、无 path 行(descriptor)
□ supported_version 正确
□ thumbnail.png 就位(<1MB)
□ 清掉调试残留(日志输出、测试 flag、临时事件)
□ Git 提交并打版本号
```
