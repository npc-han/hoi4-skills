# HOI4 常见报错解读（Error Dictionary）

报错字典：从 error.log 报错文本反推原因与修复方法。

**使用前提**：游戏以 `-debug` 启动参数运行时，error.log 才会记录完整报错。开发期间必须使用 `-debug`。

---

## 0. 三种失败模式（先判断属于哪一种再排查）

| 失败模式 | 信号 | 排查路径 |
|---|---|---|
| **CTD**（闪退） | 游戏直接退出，无报错提示 | 看 `setup.log` 最后读取的文件 → 二分搜索法（见 hoi4-mod-workflow） |
| **error.log 硬错误** | 日志有条目，通常带文件路径和行号 | 按本字典分类查原因 → 修复 → 清空 error.log 重测 |
| **静默失败**（最危险） | 功能不生效，日志完全干净 | 查文末"静默失败清单" |

---

## 1. error.log 条目格式解读

一条报错的格式：

```
[effect.cpp:402]: Invalid effect 'political_power_daily' in common/national_focus/katarland.txt line : 1997
```

拆解：
- `[effect.cpp:402]` — 游戏引擎内部源码位置（C++ 文件+行号），**不是你的文件**。但前缀的 cpp 名提示错误类型：`effect.cpp`=效果错误、`trigger.cpp`=条件错误、`pdxscript.cpp`=语法/变量错误、`texturehandler.cpp`=贴图错误、`gui.cpp`=界面错误、`eventmanager.cpp`=事件错误。
- `Invalid effect 'xxx'` — 错误内容：`xxx` 是**出问题的关键字**。
- `in common/national_focus/katarland.txt line : 1997` — **你的文件路径和行号**，第一步就是去这里看。

真实示例：

```
[effect.cpp:402]: Invalid effect 'can_research' in common/national_focus/katarland.txt line : 2016
```
→ `can_research` 是 trigger（条件），被误写在了 effect（效果）位置。

```
[trigger.cpp:114]: Trigger failed to validate: common/scripted_effects/BLT_scripted_effects.txt:77: has_game_rule
```
→ 第 77 行的 `has_game_rule` 引用了不存在的 game rule（对象未定义）。

```
[11:00:00][pdxscript.cpp:382]: Unknown variable "test_var" (file: common/scripted_effects/00_test.txt, line: 3)
```
→ 变量 `test_var` 未定义或未用 `var:` 前缀读取。

## 2. 报错字典分类表

### 2.1 未知关键字（最常见）

| 报错文本模式 | 根因 | 修复 |
|---|---|---|
| `Invalid effect 'xxx'` / `Unknown effect-type: xxx` | ① 拼写错误 ② 版本不识别（旧版 effect 在新版被移除/改名）③ **trigger 误用为 effect**（如 `can_research`、`has_xxx` 写在效果位置） | 查 **hoi4-code-reference** 确认正确 effect 名；区分四类关键字（effect/trigger/modifier/scope）；版本问题查 **hoi4-version-migration** |
| `Unknown trigger "xxx"` / `Trigger failed to validate ... xxx` | ① 拼写错误 ② 引用的对象（game rule、idea、focus 等）未定义 | 查 trigger 表；确认引用的对象已定义且名字逐字一致（大小写敏感） |
| `Unknown modifier "xxx"` | ① modifier 名拼写错误 ② 作用域不对（country modifier 用在 state） | 查 `references/documentation/modifiers_documentation.md` 或 `钢4国家精神代码.txt` |

### 2.2 变量错误

| 报错文本模式 | 根因 | 修复 |
|---|---|---|
| `Unknown variable "xxx"` | 变量未定义（未 `set_variable`）或拼写不一致 | 确认变量名逐字一致；先 set 再读 |
| `invalid database object for effect/trigger ... use var:var_name to explicitly use variables in effects/triggers` | 把一个变量名当成了对象 ID（如把变量放进只接受 tag/ID 的位置） | 读取变量时加 `var:` 前缀：`var:my_var`；写入用 `var = my_var`（无冒号） |
| `expected constant` / `expected number` | 变量/对象用在了只接受常量或数字的位置 | 检查参数类型：flag 名要字符串、数量要数字 |

### 2.3 作用域错误

| 报错文本模式 | 根因 | 修复 |
|---|---|---|
| `invalid scope` / `not in scope` | 关键字运行在不支持的 scope（如 state 专属 effect 用在 country） | 查关键字文档确认 scope 要求；用 `FROM` / `owner` / `capital_scope` 等切换到正确 scope |
| effect 在错误作用域被**静默跳过** | 作用域不匹配时游戏直接跳过该行 | 用 `if = { limit = { <scope 检查> } }` 包裹，避免无效作用域求值 |
| `FROM.FROM.FROM` 链断裂 | 跨事件边界链式引用不可靠 | 改用 `save_event_target_as` / `save_global_event_target_as` |

### 2.4 解析错误（语法）

| 报错文本模式 | 根因 | 修复 |
|---|---|---|
| `Malformed block` | 花括号 `{ }` 不配对 / 嵌套错误 | 数括号；用 VS Code + CWTools 自动检查 |
| `Unexpected token "xxx"` | ① 缺少逗号/等号 ② 引号未闭合 ③ 中文字符混入代码 ④ 反斜杠路径转义 | 看 `xxx` 是什么 token；检查该行附近；确保全角标点替换为半角 |
| `Malformed number` / `expected float` | 数字格式错误（如 `0.05` 写成 `0,05`） | 使用半角小数点 |

### 2.5 事件错误

| 报错文本模式 | 根因 | 修复 |
|---|---|---|
| `Could not fire event "xxx"` | ① 事件 ID 不存在 ② 事件未定义时被引用 ③ 缺 `add_namespace`（事件文件顶部必须声明） | 文件顶部加 `add_namespace = my_mod`；确认事件 ID 拼写 |
| 事件文件整文件不生效 | 缺 `add_namespace` 或文件未被正确加载 | 检查文件放对位置（`events/` 根目录）、命名、编码 |
| 事件选项后无效果 | option 里用了 trigger 而非 effect | 确认 option 块内是 effect |

### 2.6 引用对象不存在

| 报错文本模式 | 根因 | 修复 |
|---|---|---|
| `xxx does not exist` / `Trigger failed to validate ... xxx` | 引用了未定义的对象：game rule、idea、focus、character、technology、country tag 等 | 用 `grep -rn "xxx"` 在整个 mod + 原版目录搜索定义处；确认拼写逐字一致（**大小写敏感**）；遵循依赖顺序（先定义再引用，见 hoi4-mod-workflow） |
| 国策树报错（focus 前提 / 完成国策无效） | focus 的 `prerequisite` 或 `complete_effect` 引用了不存在的 focus ID | 确认 focus ID 唯一且拼写一致；`tdebug` 下用 Nudge 检查 |

### 2.7 本地化错误

| 报错文本模式 / 症状 | 根因 | 修复 |
|---|---|---|
| 游戏内显示原始 key（如 `my_mod.1.t`） | 缺本地化条目 / 文件未加载 | 每个 key 都建 `xxx:0 "文本"` 条目 |
| 本地化文件整文件报错（error.log 或 text.log） | ① 文件无 UTF-8 **BOM** ② 首行不是 `l_english:` / `l_simp_chinese:` ③ 文件名不以 `_l_english.yml` 结尾 ④ 扩展名实际是 `.yml.txt`（Windows 隐藏扩展名） | 用带 BOM 的 UTF-8 保存；首行写语言键；文件名 `xxx_l_english.yml`；关闭 Windows"隐藏已知文件扩展名"检查真实扩展名 |
| text.log 报 key 冲突 | 两个文件定义了同一个 key | 检查冲突；用 `localisation/english/replace/` 覆盖原版键 |
| 中文乱码 | 编码不是 UTF-8 或首行语言键与文件名语言不符 | 统一 UTF-8 with BOM；`l_simp_chinese:` 配 `_l_simp_chinese.yml` |

### 2.8 GFX / 贴图错误

| 报错文本模式 / 症状 | 根因 | 修复 |
|---|---|---|
| `Could not find texture "gfx/xxx.dds"` | 贴图路径错误 / 文件不存在 / 文件名拼错 | 检查 mod 内实际路径（**正斜杠 `/`**）；确认 `.dds` 文件存在且未损坏 |
| `Could not find sprite type "GFX_xxx"` | spriteType 未注册或名字不匹配 | 在 `interface/*.gfx` 注册同名 spriteType；名字**大小写敏感**、无多余空格 |
| 图标显示默认 `unknown.png` | 引用的 spriteType 不存在 | 同上；检查是否写成了 `GFX_idea_GFX_xxx` **双前缀**（picture 参数不要重复加 `GFX_idea_` 前缀） |
| sprite 全透明 | 链接的贴图文件不存在 | 检查路径与文件名、正斜杠、扩展名 |
| 整个 mod 所有图片失效 | `.gfx` 文件放错了文件夹 | `.gfx` 注册文件放 `interface/`（不是 `common/interface/`） |

### 2.9 GUI 错误

| 报错文本模式 | 根因 | 修复 |
|---|---|---|
| `Window "xxx" not found` | 引用的 GUI 窗口未定义 | 确认 `.gui` 文件加载；窗口名大小写一致 |
| `Could not find ... in gui` | gui 文件语法错误 | 检查 `.gui` 文件括号配对；用 CWTools 检查 |
| 按钮/图标布局错乱 | position/size 值类型错误 | 检查数值与 `@const` 常量定义 |

### 2.10 国策 / 科技 / 决议引用错误

| 报错文本模式 | 根因 | 修复 |
|---|---|---|
| 国策不显示 / 不生效 | ① `available` 块放了 effect（只接受 trigger）② 引用的 idea/event 未定义 | `available` 只放条件；effect 放 `complete_effect`；先定义再引用 |
| 科技研究后无效 | `research_cost`/`start_year` 格式错；引用的 `path` 前提科技不存在 | 查 hoi4-code-reference 科技语法表；确认前提科技 ID 存在 |
| 决议不显示 / 不能点 | `allowed`/`available`/`visible` 用错位置或放了 effect | `allowed`=能否执行、`available`=能否显示、`visible`=是否可见；都是 trigger |

### 2.11 OOB / 军队错误

| 报错文本模式 / 症状 | 根因 | 修复 |
|---|---|---|
| 选国家时 CTD | ① 国家无有效 `capital` ② 海军 OOB 用了 1.12 前旧格式 | history 文件加 `capital = <state_id>`；更新空母格式（见 hoi4-version-migration） |
| 部队不出现 / 单位缺失 | OOB 引用了未定义的装备或单位类型 | 确认 `equipment` 类型 ID 存在；确认 `oob` 在 history 中正确加载 |

### 2.12 CTD 类

| 时机 | 常见根因 | 排查 |
|---|---|---|
| 加载时 CTD | replace_path 删掉了原版必需文件；地图 BMP 损坏；省份 ID 无效 | `setup.log` 最后一行 = 崩溃前读取的文件；二分搜索 |
| 选国家时 CTD | 无 capital；OOB 旧格式；AI 模板缺失 | 见 2.11；检查 AI 模板 |
| 游戏中 CTD | 建筑位置失效；AI 引用未拥有州 | Nudge! → Find Error → Validate in State |

详细流程见 **hoi4-mod-workflow** 的 Crash Causes by Timing 表与二分搜索法。

## 3. 静默失败清单（无任何报错，但功能不生效）

报错字典查不到时，按此清单逐项排查。**这条清单比任何报错都难查，优先怀疑**：

| # | 症状 | 静默根因 |
|---|---|---|
| 1 | 旧版能用的 effect 不生效 | 版本更新后 effect 被改名/移除（旧名解析成功但什么都不做）→ 查 hoi4-version-migration |
| 2 | `set_country_flag` 后用 `has_global_flag` 检查 | flag 类型必须匹配，否则静默返回 false |
| 3 | 事件不触发 | 缺 `add_namespace`（最经典）或事件文件未加载 |
| 4 | 事件跨文件引用失效 | `FROM` 链跨事件边界断裂 → 用 `save_global_event_target_as` |
| 5 | effect 在错误作用域被跳过 | 作用域不匹配时静默跳过该行 |
| 6 | `.txt` 文件编码错误（非 UTF-8） | 游戏**静默跳过**整个文件，一个报错都没有 |
| 7 | `.yml` 缺 BOM 或首行错 | 所有字符串显示为原始 key |
| 8 | 覆盖了原版同名文件但没生效 | 覆盖规则=整个文件替换；确认文件名与路径与原版逐字一致 |
| 9 | 两个文件定义同名 ID | 后加载的静默覆盖先加载的（按 ASCII 排序） |
| 10 | `descriptor.mod` 与 `.mod` 的 name 不一致 | 启动器与游戏读到的 mod 名不同 |
| 11 | path 用反斜杠 | 反斜杠被当转义字符，路径解析失败 |
| 12 | 图标空白 | `icon = GFX_xxx` 无对应 spriteType 注册 |

## 4. 报错排查决策树

```
收到报错/功能异常
│
├─ 游戏闪退？ ──────────────→ CTD 模式
│                              │ setup.log 最后读取的文件 = 头号嫌疑
│                              │ 二分搜索法定位 → 修复 → 重测
│
├─ error.log 有条目？ ───────→ 硬错误模式
│                              │ 读 [xxx.cpp]: 前缀判断错误类型
│                              │ 读 in <文件> line : <行号>
│                              │ 按本字典分类表查原因 → 修复
│                              │ 清空 error.log → 重测 → 确认无新条目
│
└─ 日志干净但功能不生效？ ──→ 静默失败模式
                               │ 逐项过"静默失败清单"（第 3 节）
                               │ 最优先：缺 add_namespace / 编码 / 依赖顺序
```

**通用铁律**：
1. 报错里的文件路径和行号指向**你的文件**，先去看那里
2. `[xxx.cpp]` 前缀只是错误类型提示，不是你的代码
3. 修完必须**清空 error.log 再测**，否则新旧报错混在一起
4. 所有 `common/` 文件夹里的报错都应修复，不能跳过（官方 Wiki：almost all errors relating to files in the common folder should be fixed）
5. 修复后关闭 -debug 前，再用 -debug 完整测试一遍
